# Historical attack tests and current interfaces

The 25 expected failures in `test_pseudonymisation_forgery.py` were also run without their markers during preparation. Ten fail on missing earlier APIs, eleven expect older diagnostics for obsolete artifact forms, and four do not reach their intended target condition. This explains their current behavior; it does not resolve the underlying requirements by declaration.

The current manual path uses explicit entity resolution and protected stores. It does not implement the earlier `ReplacementTable.pseudonym_for(name, type)` interface. Related tests are mapped below. Names refer to the tests in `tests/`.

| Historical requirement | Related current tests | Scope or remaining difference |
|---|---|---|
| A4, E1, E6: no descriptive processing before required review | `test_spur_p4a::test_no_original_edge`, `test_spur_p4c::test_finalisation_and_gate`, `test_spur_p4b::test_empty_accept_does_not_open_final` | Tests the manual graph and its consumers. The legacy `childlux` model-based path is unimplemented. |
| A5, B5, D1: no new plaintext copies in ordinary artifacts or reports | `test_spur_p4b::test_exact_original_inventory_and_leak_oracle`, `test_spur_p4c::test_public_inventory_and_negative_leaks` | Inspects generated synthetic material and includes deliberately injected negative controls. It is not an exhaustive leak detector or detection-quality test. |
| A6: changes invalidate dependent results | `test_spur_p4b::test_actor_change_and_source_reactivation`, `test_spur_p4c::test_two_record_convergence`, `test_spur_p4c::test_consumer_does_not_publish_after_registry_change` | Tests current source/register bindings and downstream use. The earlier two-table reanchoring scenario has not been ported verbatim. |
| B2: invalid span positions are rejected | `test_spur_p4b::test_closed_position_contract` | Exercises current capsule validation, including empty, negative, out-of-range and overlapping positions. The old `spans.recorded` representation is not the current protected capsule. |
| C1, C2: stable identity and distinct pseudonyms | `test_spur_p4c::test_two_record_convergence`, `test_spur_p4c::test_stable_batch_merge_split_and_no_reuse` | Identity decisions are explicit and scoped; name-string equality is not used as proof of identity. |
| C3, C8: missing or inconsistent register state must stop | `test_spur_p4c::test_configuration_and_integrity`, `test_spur_p4c::test_initialisation_never_adopts_unproven_state` | Tests missing state, rollback, keys and integrity in the current register implementation. |
| C5: concurrent allocation must not collide | `test_spur_p4c::test_two_process_registry_cas` | Uses two actual processes and checks retry/convergence. It does not reproduce the old eight-process stress scenario. |
| C6, C7: separate stores and keys | `test_storage_placement::test_current_stores_reject_unsafe_placement_and_key_reuse`, `test_storage_placement::test_separate_external_stores_with_distinct_keys_remain_usable`; related `test_spur_p4c::test_configuration_and_integrity` | Eleven targeted rejection cases and a valid configuration cover overlapping stores, storage or configuration inside the workspace, keys inside stores and key reuse. These use the current constructors; they do not recreate the earlier table API. |
| C9: deterministic changes with preserved surrounding material | `test_spur_p4b::test_unicode_renderer_all_types`, `test_spur_p4c::test_renderer_all_types_and_report_offsets` | Tests actual configured transformations, Unicode and output offsets; no generative rewriting is involved in this step. |
| D6: review binds the output and its basis | `test_spur_p4c::test_review_window_rechecks`, `test_spur_p4c::test_wrong_displayed_text_is_not_a_gate`, `test_spur_p4c::test_policy_change_after_cipher_prevents_publication` | Tests the current final-text and report review window. |
| E4: configuration must not silently remove the duty | `test_spur_p4a::test_invalid_configuration_is_exit_2`, `test_spur_p4c::test_recovery_rechecks_policy_before_final_text_accept` | Current profile validation and policy changes are covered; this does not grant authority to arbitrary profile files. |

The historical tests and their markers are retained. A mapped passing test is not automatically equivalent to an older assertion. Extending this mapping requires checking the actual stimulus and target assertion, not matching test names or counting green cases.
